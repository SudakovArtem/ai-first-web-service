# AI Bug Triage

Учебный проект трека **AI-First Web Service / SaaS Backend** (eot-2611). Цель проекта — помочь инженеру разобраться в веб-баге. По баг-репорту сервис будет подбирать похожие случаи и документацию, предлагать диагностические проверки и отмечать, каких данных не хватает.

## ДЗ №1

Первый этап — HTTP API для приёма и просмотра баг-репортов. Стек — Node.js 24, TypeScript и Fastify. Тикеты хранятся в памяти процесса и сбрасываются при перезапуске. Для запуска достаточно Node.js и npm.

```sh
npm ci
npm run check
npm start
```

Сервер слушает `127.0.0.1:3000`. Порт можно изменить, например `PORT=3001 npm start`. `npm run check` запускает линтер и проверку типов. Если одна из проверок завершается с ошибкой, команда возвращает ненулевой код.

## Пример работы

В другом терминале выполните:

```sh
curl -fsS http://127.0.0.1:3000/health

curl -fsSi http://127.0.0.1:3000/tickets \
  -H 'Content-Type: application/json' \
  -d '{"title":"Настройки сбрасываются после обновления страницы","description":"После сохранения уведомление показывает успех, но после обновления страницы видны старые значения."}'

curl -fsS http://127.0.0.1:3000/tickets
```

`GET /health` возвращает `200` и `{"status":"ok"}`. Создание тикета возвращает `201`, идентификатор и дату создания. Список содержит только тикеты текущего запуска. Пустой заголовок, отсутствующее описание и другие нарушения схемы дают `400`.

## Следующие этапы

Добавить к тикету структурированный AI-ответ, поиск по синтетическим кейсам и документации, один MCP-инструмент чтения тикетов и набор Evals. Для первого обращения к модели можно использовать бесплатный маршрутизатор [`openrouter/free`](https://openrouter.ai/openrouter/free). Для сравнительных прогонов Evals выбрать конкретную доступную модель и фиксировать её ID вместе с результатами.
